# M4 walkthrough — knowledge layer

## What was built

M4 turns a Snapshot into the numbered facts the model may cite. The sources are the scan, OBDex (9,533 generic codes, compiled to SQLite), Wal33D (labelled VW P1xxx hints) and NHTSA (recalls and complaints, through a cached client and a resolver for NHTSA's inconsistent model names). `prefetch()` writes them into an `EvidenceStore` in a fixed order, so a scan always gets the same IDs. `derive()` adds computed facts such as total fuel trim. `agent/safety.py` holds the escalation rules, which never involve the model. `obdient nhtsa` shows what NHTSA returns and under which names.

## How data flows

```text
Snapshot ──┐
           ├─ prefetch(): user report, codes, definitions/hints/gaps, freeze frame, readiness,
OBDex ─────┤              since-clear, live readings, derive(), recalls, complaint summary, gaps
NhtsaResolver ┘                                   │
                                                  ▼
                                        EvidenceStore (E1..En) ──► safety.evaluate() ──► Escalations
```

Read first:

1. [knowledge/evidence.py](../../src/obdient/knowledge/evidence.py), `prefetch`. Its eleven numbered comments are the eleven steps of SPEC §5.6; everything the model will see comes out of this one function.
2. [agent/safety.py](../../src/obdient/agent/safety.py), `evaluate`. It holds every rule that can put a banner above the findings.
3. [knowledge/nhtsa.py](../../src/obdient/knowledge/nhtsa.py), `NhtsaResolver.resolve`. Short, and it is the fix for the product's founding bug.

## Decisions SPEC and PLAN did not dictate

| Decision | Alternative rejected |
| --- | --- |
| Tiers by source host; 57 manufacturer and supplier hosts. `saabwisonline.com` is out. | Counting re-hosted manuals, chip datasheets and regulators. |
| The index stores a fingerprint of the commit and host list, and rebuilds when it changes. | Commit only in the file name, which kept stale tiers after a list edit. |
| HTTP 400 with an empty result body is "no records". | Treating it as a failure, which hid "0 recalls under Golf GTI". |
| Offline mode uses cache rows of any age. | Refusing rows older than 24 hours. |
| A read error's detail is never shown for parse errors or mode 09. | Copying it, which put a failed VIN reply into evidence as hex. |
| P3 judges each phase and each `read_live_data` call separately. | Grouping by condition only, which paired rpm from one call with voltage from another. |

## Why limp mode is a label, not an escalation

OBDex marks a code "limp mode possible" when *some* manufacturer can cut power for it: 4,915 of 9,533 codes. As a PROMPT rule it fired on s02 (a pending MAF code), s03, s05 and s10. A banner that appears for half of all codes carries no information and crowds the rare banners that matter (overheating, brakes). Whether *this* car will limp is not something OBDex or a scan can say.

So the flag is kept as information: the code's entry in the report gets the label "OBDex: can trigger reduced-power (limp) mode". PROMPT is left with two rules that describe this car, not the code in general: misfire codes, and low voltage with the engine running (SPEC X13).

## One example, end to end: s01

`collect()` gives the Snapshot from M3. `resolve_for_scenario` reads `tests/fixtures/nhtsa/gti_2018/`:

1. `candidate_names("VOLKSWAGEN", "Golf GTI")` gives the name as given, then without the family prefix `Golf`: `["Golf GTI", "GTI"]`.
2. Recalls for "Golf GTI": `recalls_golf_gti.json`, zero results. NHTSA really sent this with HTTP 400.
3. Recalls for "GTI": 3 results, each with `matched_names = ["GTI"]`. Complaints: 33 under "Golf GTI" and 17 under "GTI", no overlap, so 50 in all.

`prefetch` then fills the store:

| ID | Kind | Summary (shortened) |
| --- | --- | --- |
| E1 | user_report | The user reports: "Slight whistle from the engine at idle". Warning lights seen: steady_mil. |
| E2 | dtc | Code P0171 is present (stored, permanent) on ECU 7E8. |
| E3 | dtc_definition | OBDex definition of P0171: System Too Lean Bank 1. Common causes: air leak after the air flow sensor; crankcase ventilation; … |
| E4 | freeze_frame | Freeze frame for P0171: coolant 88 °C, STFT bank 1 +6.2 %, LTFT bank 1 +19.5 %, engine speed 780 rpm. |
| E5 | readiness | All 7 supported monitors are complete. |
| E6 | since_clear | 45 warm-ups, 820 km. |
| E7–E12 | live_reading | Six PIDs at hold_2500, e.g. E8 STFT −12.0 %, E9 LTFT +19.5 %. |
| E13–E18 | live_reading | The same six at idle, e.g. E14 STFT +6.2 %, E15 LTFT +19.5 %. |
| E19–E21 | derived | Total fuel trim at hold_2500, idle, and in the freeze frame. |
| E22 | derived | Trim change idle → hold_2500: −18.2 %. |
| E23–E25 | derived | MAF within band; 0 of 4 monitors incomplete; no sign of a recent clear. |
| E26–E28 | recall | 24V110000 (fuel system), 19V615000 (anti-theft), 18V369000 (brake calipers), each found under GTI. |
| E29 | complaint | 50 owner complaints on file under names: Golf GTI, GTI (unverified). |

The derived item E20 is computed in `_total_trims`:

- It finds `live:0106:idle:0` (E14) and `live:0107:idle:0` (E15) by dedupe key.
- It adds their means: 6.2 + 19.5 = 25.7.
- The payload is `{"metric": "total_fuel_trim", "inputs": ["E14", "E15"], "total": {"value": 25.7, "unit": "%"}, …}`.

The store refuses bare numbers, so M6's verifier can match each number the model writes to a cited item. At hold_2500 the total is +7.5 % (E19); the −18.2 % change (E22) is the leak signature.

`evaluate` gives no graded escalation. Only `R1_safety_recall` fires: two of the three recalls touch the fuel system and the brakes. It is a notice, never graded.

## Surprises and things to double-check

- **The VIN could have reached the model** through a parse-error detail. The adapter layer still records the raw hex, so M5 must not show `read_errors` raw.
- **Your `vpic_decode.json` keeps `VehicleDescriptor: 3VW547AU*JM`**, a VIN pattern rather than your VIN. The code drops it; the fixture file still has it.
- **OBDex is GM- and Ford-heavy:** `gsi.ext.gm.com` alone makes 3,942 codes tier 1. "Tier 1" means a manufacturer documented the code, not that VW did.
- **Slow warm-up uses a phase's mean run time** (V17), to check in M8.

## Quiz

1. Why does s01 have no "none found" gap for recalls even though "Golf GTI" returned nothing?
2. E22 says −18.2 %. Which two evidence items is it built from, and which items are they built from?
3. P0299 is flagged limp-mode capable. What does s05's report show for that, and why no PROMPT?
4. The network is down and you run `obdient nhtsa --offline` a week after a lookup. What happens?
5. A VIN reply fails to parse. What does the model see about it?

### Answers (spoilers)

1. "GTI" found 3 recalls. The gap is added only when the union over all names is empty.
2. E20 (idle total) and E19 (hold_2500 total); those come from E14 + E15 and E8 + E9.
3. The label "OBDex: can trigger reduced-power (limp) mode" on the P0299 code entry. The flag is set on half of all codes, so as a banner it would carry no information (X13).
4. It answers from the week-old cache rows; offline mode accepts any age.
5. `Reading 0902 failed: PARSE ERROR.`, with no detail, because mode 09 details can hold the VIN.
